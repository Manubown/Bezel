# Outside view: code review of the integration branch, and what to do about each finding

Reviewed 2026-11-13: `git diff master...outside-view` at `ad642d7` (147 files), by two read-only reviewers, one against the repo's documented standards and a fixed list of code smells, one against `spec.md` and the tickets' boxes. Neither found a runtime bug or anything from the spec's Out of Scope list. On that commit: `pnpm typecheck` clean, `pnpm test` 381 passed in 45 files, `pnpm pages --here` passed (Node 22.23.5).

Each item says what was found and the decision. "Fix" items are one piece of work for one implementer; tick them here as they land.

## A. What a player sees

- [ ] **A1 Makers' words still reach players.** A joined phone's card reads "Connection lost · The host phone restarted" or the runtime's own detail; Start refusals read "needs 1–2 Tiles; 3 present", "2 Players; 1 seated" (the close reasons and `HOST_RESTARTED` in the result module; the lobby's refusals). Spec D5. **Fix:** players' words for every close reason and every refusal ("first phone", "phones on the table", "players"); the runtime's detail shows in Maker mode only; the troubleshooting guide quotes the new refusals verbatim (CONTRIBUTING, "Changing the lobby").
- [ ] **A2 Two cards at once.** When a joined phone's 30 s grace runs out, the "Connection lost" result card and the help card both show, one over the other (tickets 04 × 06). **Fix:** the help card waits until the result card is closed; cover it in the pure function's tests.
- [ ] **A3 The Sound chip squeezes the strip** (tickets 10 × 04): at 390 px the status line and the second line are cut with an ellipsis (a reviewer's arithmetic, not run). **Fix:** check it in a browser at 390 and 360 px with the longest lines ("Lost the table. Reconnecting…"); the status line must never be cut. Drop the placement hint from the strip's second line (the canvas shows it large since ticket 05; it was on screen twice) and show the Player's name there in the Player's colour (ticket 09 left it grey).
- [ ] **A4 The first phone's advice line never clears** when the dropping phone stays away. Spec D7. **Fix:** the streak expires; test it.
- [ ] **A5 "match" and "game" both reach players** ("A match is on" beside "starts the next game"; "Last match: Game ended on the first phone"). **Fix:** players read "game" for a Match everywhere (app and site); add it to `GLOSSARY.md` under "Words players read" (lower-case "game": what the app and the site call a Match when they speak to players; code and developer docs say Match). The privacy page says "a log of what happened on this phone", not "the session log".
- [ ] **A6 A joined phone can lose its install offer unseen:** the first phone pressing Play again closes the card that carried it, and a joined phone has no permanent row. Spec D13, story 29. **Fix:** the offer is spent only when the person closes that card themselves or uses the offer; a card replaced by the next Match brings it back on the next result card.
- [ ] **A7 The Game pick is remembered per table code only** (it survives a reload, not a new visit). Story 6. **Fix:** the last picked Game is kept on the Device and used on the next visit if the shown list has it; add its line to the privacy page's list of what the phone keeps.
- [ ] **A8 The legal pages do not have the look.** Spec D15. **Fix:** privacy and imprint render inside the site's shared page layout (tokens, face, icon, preview tags, sitemap); remove the second shell and the comment that describes a plan; the test that claims "the layout every page shares" becomes true.
- [ ] **A9 "Works on" says two things:** the site "a current Safari or Chrome", the README "Untested: Chrome". **Fix:** one sentence in both, saying only what the records show (`.scratch/live-test-1/findings.md`, `docs/PLAN.md` §6).
- [ ] **A10 The changelog says scores use the display face;** in a Game they are drawn in the system face (a Game imports `@mgc/sdk` only). **Fix:** reword the changelog line.
- [ ] **A11 The audio session is set by the Games,** page-wide, even while Sound is off. Spec D12. **Fix:** the platform sets it, only while that Device's Sound is on; the Games do not touch `navigator`'s audio session.

## B. Code and documents

- [ ] **B1 Player words in code and developer docs.** `GLOSSARY.md`: code and developer docs say Session and Host. Comments in the new app modules, a few guide sentences and identifiers (`tableCode`, `otherTable`, `joinTable`, the module's file name) say "table". **Fix:** Session and Host everywhere outside quoted UI strings; rename the identifiers and the file (mind `joinSession`, which `@mgc/core` already exports).
- [ ] **B2 "Arrangement" as an identifier** (`GLOSSARY.md`, Layout: avoid "arrangement"; the code's word is template). **Fix:** rename (`arrangements()`, `ARRANGEMENT`, the site's fields) to template words; the UI strings stay.
- [ ] **B3 The table code is read four ways** (one reader, one inline copy, one that only upper-cases, the site's length rule; `maxlength="4"` typed twice; the sheet's join form builds its own address and drops the flags). **Fix:** one reader, one length constant, one address builder, used by the app's two forms, the start-up code and the site.
- [ ] **B4 "Installed" is decided three ways** (the install module, the site's forward script, the app's start-up). **Fix:** one exported query that all three use (the site's inline script gets it at build time).
- [ ] **B5 The site imports the app's stateful lobby module** for one pure function. **Fix:** move that function to the pure Game-list module; the app package exports to the site only modules that are pure when loaded; say so in a comment at the exports and in `docs/architecture.md`.
- [ ] **B6 `docs/architecture.md` no longer matches the dependencies:** `@mgc/look` and the site have no row or arrow. **Fix:** add them.
- [ ] **B7 Grid columns are derived three times** (the layout package, the placement sentence, the site's pictogram, the last by a different rule). **Fix:** export the rule from `@mgc/layout` and use it in all three.
- [ ] **B8 One shape declared three times:** `{ headline, detail, player? }` in the result, pause and HUD modules. **Fix:** one type.
- [ ] **B9 Names that do not say what they hold:** `inHand` and `held` in the lobby (`held` is true for any stored role), `Installer.finished()` beside `Situation.finished`. **Fix:** rename.
- [ ] **B10 More than the spec asked:** four off-values for Maker mode where D3 names "no"; exports used only in their own file (`IN_APP_BROWSERS`, `FEATURED`, `SHOWN_MS`, and `PLAYER_COLOURS` if nothing outside the SDK uses it); the install module stores `'yes'` where the other settings store `'on'`/`'off'`. **Fix:** "no" only (and the guide's flag row); unexport; one way to store a switch. A phone that already stored the old value must still read correctly.
- [ ] **B11 The privacy page's relays, STUN servers and Relay host are typed constants with no test.** Ticket 14: "read from the build's actual configuration". **Fix:** a test that computes the signaling relays the way the transport does (the installed library's list and its selection by the app's id) and compares; the Relay paragraph says "when the build carries a Relay".
- [ ] **B12 Stale sentences outside the tickets' files:** `scripts/new-game.mjs` prints that the Host's Game list shows the new Game (true only in Maker mode); `docs/README.md` says the log folder holds live test 1 only. **Fix:** both.
- [ ] **B13 Screenshots.** Six tickets tick "screenshots in a comment" and the spec's Testing Decisions say "screenshots attached to the ticket", but the implementers were told to describe screens in words and commit none. **Fix:** capture one final set on this branch at 390×844 into `.scratch/outside-view/img/` (first phone's sheet; a joined phone in the lobby; the help card; Pong before the first touch and in play; the result card on the first phone and on a joined phone with the install offer; the site's home page, privacy and imprint), list them at the end of `spec.md` under Further Notes, and reword the spec's Testing Decision to what was done: each ticket's comment describes its screens in words, and one final set of pictures is attached to the spec.
- [ ] **B14 The guide's `path:line` citations** (CONTRIBUTING: a citation is a claim about that line). Many point into the old HUD file or shifted lines. **Fix, last, after every other item:** re-anchor every citation in `docs/guide/` with the script `.scratch/dev-onboarding/issues/02-developer-guide.md` describes; 0 out of range, and each re-anchored line read to confirm it is the line the sentence talks about.

## C. Decided against, with the reason

- **The ball trail and the synth are written once in each of the two Games.** Left: a Game imports `@mgc/sdk` only, and a drawing or sound helper there would be a second public surface to keep stable; `docs/guide/concepts.md` already says each Game carries its own.

- **Play again refuses when a phone joined since the last game.** Left as ticket 06 built it; the makers were told and can change it.
