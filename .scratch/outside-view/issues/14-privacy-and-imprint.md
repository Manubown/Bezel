# 14: Privacy and imprint pages

**What to build:** The site has a privacy page that says, in plain words, what a phone gives away and to whom, and an imprint page. Both are complete except for the makers' own details, which are marked blanks; the app links to the privacy page (spec D18). Not legal advice: the makers read both before the site is linked anywhere.

**Blocked by:** 12

**Status:** resolved

- [x] The privacy page names every party a phone talks to and what each sees: the host of the pages; the public signaling relays (which see an IP address and the table's hashed name); the Relay provider (which carries encrypted traffic when no direct path works); the other phones of the table (which see each other's IP address, as any direct connection does)

**Where each fact on the privacy page comes from**
- GitHub Pages is the host: `.github/workflows/pages.yml` (`actions/deploy-pages`), `brand.json`'s address `https://manubown.github.io/Bezel/`. That it logs visitors' IP addresses: GitHub's "What is GitHub Pages?", section Data collection ("the visitor's IP address is logged and stored for security purposes"). That the address with `?room=CODE` reaches it: the QR is the page's own URL with `?room=` (`hud/sheet.ts` `joinUrl`), and the joining phone's first request was `GET …/play/?room=9AXS` in the browser check. No cookie from GitHub Pages: `curl -I` of `/Bezel/`, `/Bezel/stable/` and `/Bezel/?room=ABCD` on 2026-11-13 had no `Set-Cookie` (Server: GitHub.com, Via: varnish).
- The signaling relays: `packages/core/src/trystero-transport.ts:73` passes `{ appId }` and no `relayConfig`; `trystero@0.26.0` re-exports `@trystero-p2p/nostr`, whose `init` calls `getRelays(config, defaultRelayUrls, defaultRedundancy = 5, true)` (`nostr/dist/index.mjs:5,199`); `getRelays` shuffles the 29 defaults with the app id as seed (`core/dist/utils.mjs:45`). Run with the installed code and `appId: 'mobilegameconnect'` (`apps/pwa/src/main.ts:18`): `wss://relay.nostr.blockhenge.com`, `relay.flashapp.me`, `relay.nostrmap.net`, `relay.bullishbounty.com`, `relay.novospes.com`, the same five as `docs/research/infrastructure-independence-and-pocket-device.md` §1.1 and the same five strings in the hosted bundle `index-qoYLyM8E.js`. What they see: the topic is the SHA-1 of `Trystero@mobilegameconnect@<CODE>` (`core/dist/strategy.mjs:39-41`), sent as the event's `x` tag (`nostr/dist/index.mjs:44-51`); offers are AES-GCM with a key from SHA-256 of `:mobilegameconnect:<CODE>` (`core/dist/crypto.mjs:12`, no password set), hence "locked with a key made from the table's code"; a code is 4 of 31 characters (`main.ts` `CODE_ALPHABET`), hence "can be worked back out"; the signing key is `schnorr.keygen()` at module load (`nostr/dist/index.mjs:8`), hence "anew each time the app opens". "Stays connected while the app is open": the five WebSockets opened at load and failing ones were reopened during the 50 s observed.
- STUN: `core/dist/peer.mjs:378` (`stun.l.google.com`, `stun1`, `stun2` on 19302, `stun.cloudflare.com:3478`), used because the app passes its Relay as `turnConfig` (`peer.mjs:18`, `iceServers: defaultIceServers.concat(turnConfig)`). In the browser the phones' connections carried exactly these four, and the joining phone had `srflx` candidates from Google and Cloudflare.
- The Relay: `apps/pwa/src/turn.ts`, `VITE_MGC_TURN_SERVERS` from the secret `MGC_TURN_SERVERS` (`pages.yml`), Metered per `docs/guide/running-on-phones.md`. The hosted build at `/Bezel/` (master, `index-qoYLyM8E.js`) holds four servers, all `standard.relay.metered.ca` (80 UDP/TCP, 443 UDP, `turns:` 443 TCP); in the browser its connections carried them. "Each phone asks the Relay … whenever it sets up a connection": an offer gathered in the browser with that build's servers got `relay` candidates from all four Metered URLs besides the `srflx` ones. Company, "we do not inspect, store or record it", "no keys to it" and "Relay connection metadata, including IP addresses: 30 days": metered.ca/privacy (version 2.0, effective 24 September 2026).
- The other phones: `deviceInfo` (`apps/pwa/src/device.ts:132-137`: id, `userAgentData.platform ?? navigator.platform`, screen size, dpr, px per mm) is what a Device announces (`packages/core/src/session.ts` `DeviceInfo`); Players' names are the lobby's; the Host routes all messages (`GLOSSARY.md`).
- Kept on the phone (`src/kept.ts`): `localStorage` `mgc.deviceIds`, `mgc.playerIds` (`device.ts:5,9`), `mgc.maker` (`maker.ts:4`, written only when the address has the flag), `mgc.matchesFinished` and `mgc.installDismissed` (`installer.ts:4,6`, ticket 11: written when a Match this phone ran is ended by its Game, `main.ts` `install.finished()`, and when a result card that carried the offer closes, `hud/cards.ts` `install.dismiss()`); `sessionStorage` `mgc.deviceId` (`device.ts:7`), `mgc.hostRoom` (`main.ts:24`), `mgc.lobby.<CODE>` (`lobby.ts:138`); IndexedDB `mgc-log-<device id>` (`recorder.ts:98`), newest 20,000 lines, ~3 MB (`recorder.ts:73`, `RecorderOptions.maxLines`), never an address (`networkOf`), the `device` line's fields (`main.ts`, the guide's log table).
