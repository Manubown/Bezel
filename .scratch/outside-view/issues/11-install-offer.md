# 11: The app offers itself for the home screen, once, after the first Match

**What to build:** After a Device's first finished Match the result card offers the app for the home screen: an Install button on Android, the steps on an iPhone (Share, Add to Home Screen), each with the reason (full screen, no browser bars). The sheet keeps a row for it. Inside another app's browser a banner says to open the page in Safari or Chrome. An installed app shows none of it (spec D13, D14).

**Blocked by:** 06, 07

**Status:** resolved

- [x] What to offer is one pure function of the platform, whether the app runs installed, whether the page is inside another app's browser, the Device's count of finished Matches and whether the offer was dismissed; unit tests cover every branch
- [x] Nothing is offered before the first finished Match, except the in-app-browser banner, which shows at once
- [x] The offer appears on the result card once; dismissed, it does not return there; the sheet's row stays
- [x] Android: the button triggers the browser's own install prompt when the browser has offered one, and falls back to the menu steps when it has not
- [x] iPhone and iPad: the steps name Share and Add to Home Screen; Chrome on iOS gets its own wording
- [x] Running installed: no offer, no row, no banner
- [x] No service worker is added
- [x] The phone guide's install section says what a phone gets and corrects the claim that an iPhone locks orientation when installed
- [x] Browser smoke with the platform emulated, screenshots in a comment: Android offer, iPhone steps, in-app-browser banner
- [x] Left for phones, as boxes on ticket 17: the real install on Safari and on Chrome, and the installed app opening full-screen

**Decisions**
- **A joined phone has no permanent row; it has the offer on the result card only.** The strip is two lines of status over the Tile ("Phone 2 of 3 · right of phone 1 · Ana"), and it lets touches through (`pointer-events: none`). A button there would compete with the placement cue and need the strip to take touches. A joined phone that becomes a first phone gets the sheet's row.
- "Once" and "dismissed" are one flag. A result card that carried the offer counts as having dismissed it once that card closes, however it closes: Play again, Change game, the bar, a tap on a joined phone's card, or the next Match. There is no separate "Not now" button: the card already has its ways out. A card that never showed (the first phone's sheet open when the Match ended) does not use the offer up.
- Finished means closed with reason `ended` (the Game ended it, with a result). An abort, a crash or a lost connection does not count.
- A computer (platform `other`) is offered nothing: the app is for phones. Desktop Chrome would offer an install too, but a laptop is not a Tile on the table.
- The banner keeps the spec's words for every platform ("Safari or Chrome"): from an iPhone in-app browser, either browser works. On the first phone it heads the sheet, above the advice line and the bar, folded or open. On a joined phone it is the strip's third line. It is hidden while a Match runs. It cannot be dismissed. There is no install offer inside another app's browser, because such a browser cannot add to the home screen.
- `beforeinstallprompt` has its default prevented, so Chrome's own install bar does not appear before the first finished Match. Chrome fires the event again after a dismissed prompt (seen in the smoke), so each tap on Install opens the browser's own dialog while Chrome offers one.
- The situation is read once per page: the HUD asks on every render, up to once per frame during a Match. `appinstalled` is the one change during the page's life.
- The banner is a warning (this browser cannot do what the app needs), so it gets the amber rule (`--warn`), as the advice line does.
